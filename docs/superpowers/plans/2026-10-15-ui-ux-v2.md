# AutoClip UI/UX v2 Implementation Plan

> **For agentic workers:** Use executing-plans inline, one phase at a time. Do not begin a phase before verifying the previous acceptance gate.

**Goal:** A consistent graphite/steel-blue desktop editorial workspace without operational regressions.

**Architecture:** Preserve App.vue coordination, existing API clients and domain rules. Establish semantic tokens and statically compiled Fluent icons first; migrate shell and presentation components incrementally afterward.

**Tech stack:** Vue 3.5.43, Element Plus 2.14.7 (installed), Vite 7.3.7, TypeScript, Tauri 2. Fluent via unplugin-icons and @iconify-json/fluent.

**Spec:** User-supplied “AutoClip — Plano de implementação UI/UX v2”, sections 1–22, including its phased acceptance gates and QA matrix.

## Global constraints

- No backend, Python contracts, queue, media pipeline, API-session or Tauri security changes.
- Keep four project destinations, list default, authenticated media recovery and human final approval.
- No remote icon loading, arbitrary external SVG, decorative gradients/glows/glass, fake counts or new advanced settings.
- Segoe UI Variable → Segoe UI → system-ui; keyboard focus, native scroll, selectable text, forced colors and reduced motion remain supported.
- Small commits by responsibility; no unrelated bulk formatting or destructive worktree operations.
- Current checkout is the requested branch and is clean; continue in place, preserving the other existing worktree.

## Review focus

1. Icon-only commands retain their accessible names and keyboard behavior after migration.
2. Selected, hovered, checked and disabled controls remain distinguishable; text contrast is tested on actual permitted surfaces.
3. Static icon imports work with networking disabled; no runtime provider or fallback fetch.
4. Partial/legacy project data never becomes invented preview/final/approval counts.
5. New overlays must preserve selection, media cleanup, focus restoration and queue independence.

### CSS audit

Tokens already feed compatibility aliases and most shared surfaces. `element-theme.css` still hardcodes white primary variants and uses broad `!important` overrides. `layouts.css`/`theme.css` contain overlapping historical rules and scoped components still contain fixed font sizes/colors. Migrate active consumers gradually; do not delete these wholesale. Phase 1 only changes token foundation, Element Plus theme and typography/control scale; layout restructuring belongs to later phases. `frontend-runbook.md` contains historical light/purple, old-preview-resolution and approval descriptions: current code plus `preview-final-validation.md` are authoritative for those behaviors.

## Phase 1 — Design system and icon sample

**Files:** tokens.css, element-theme.css, theme.css, desktop.css as needed; components/ui/AppIcon.vue and typed icon registry; vite.config.ts, package manifests/types; App.vue, ProjectLibrary.vue and selected playback/queue consumers; focused tests.

**Interfaces:** `AppIcon` names are a fixed semantic union; `size: sm | md | lg` → 16/20/24 px, `variant: regular | filled`, decorative by default. Informative icons receive role/img and an accessible label; icon-only parent commands keep their own label. Imports are explicit `~icons/fluent/...`, `compiler: vue3`, automatic installation disabled.
